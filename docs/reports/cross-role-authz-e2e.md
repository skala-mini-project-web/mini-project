# Cross-role authorization browser E2E receipt

This QA is accepted only from a real localhost frontend, Spring backend, AI service, and two isolated browser sessions. Mocked routes and seeded business records are not used. The script creates a uniquely named product from the repository's synthetic financial corpus fixture.

## Run

```bash
node frontend/scripts/real-cross-role-authz-e2e.mjs
```

Optional environment variables:

- `AUTHZ_FRONTEND_URL` (default `http://127.0.0.1:5173`)
- `AUTHZ_BACKEND_URL` (default `http://127.0.0.1:8080`)
- `AUTHZ_AI_URL` (default `http://127.0.0.1:8000`)
- `AUTHZ_HEADLESS=false` to show Chromium
- `CROSS_ROLE_AUTHZ_E2E_RECEIPT` to override the receipt path
- `PLAYWRIGHT_EXECUTABLE_PATH` when the browser is not Playwright-managed

The default immutable JSON receipt is `docs/reports/runtime/cross-role-authz-e2e-<run-key>.json`. A failed run also writes a receipt before returning a non-zero exit.

## Assertions

The real reviewer session sends direct requests—not UI visibility checks—and receives `403 FORBIDDEN` for:

- confirmed document text mutation;
- document extraction retry;
- batch cancel and quarantine;
- batch-item cancel, quarantine, and retry.

The script snapshots the terminal document, batch, and item through the PM session before these calls and compares their persisted business state after every forbidden request has completed.

The real PM session sends direct requests and receives `403 FORBIDDEN` for:

- review decision;
- Risk Pattern mutation;
- GuardFit creation and full-update mutation.

The forbidden PM decision is followed by a reviewer read proving the review remains `PENDING`. The valid reviewer path creates a synthetic GuardFit draft; reviewer reads before and after the forbidden PM update prove its persisted state is unchanged.

For the negative review path, two distinct analyses are produced from the synthetic confirmed document. One reviewer approval creates a synthetic Risk Pattern solely as the authorization target. The second review is rejected with an empty finding selection. The script proves that:

- the rejection response is `REJECTED` with no Risk Pattern IDs;
- the reviewer Risk Pattern ID set is unchanged across rejection;
- the PM API session reads the persisted rejection comment and no promotion;
- the PM browser renders `반려됨` and the persisted rejection comment.

## Browser and API evidence

The receipt includes service URLs, fixture checksum, isolated actor identities, created resource IDs, every expected forbidden request, the unchanged-state result, rejection/no-promotion results, and these browser signals:

- page errors;
- console errors;
- request failures;
- all observed API responses;
- unexpected non-2xx API responses.

A passing receipt requires page errors, request failures, unexpected API responses, and unexpected console errors to be empty. Chromium may emit a generic resource console error for an intentional `403`; those messages are bounded by the observed forbidden-response count and recorded separately as expected authorization evidence.
